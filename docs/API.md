# API contracts and compatibility

Reviewed 2026-11-06. Current official sources: [TypeSafe OpenAPI](https://docs.typesafe.ai/api/system-one.md), [OpenAI create](https://developers.openai.com/api/reference/resources/decisions/methods/create), [OpenAI guide](https://developers.openai.com/api/docs/guides/decisions), [H2O shim](https://huggingface.co/h2oai/h2o-lightning-4b/raw/main/h2o_lightning_shim.py). Documentation/source inspection only; no live provider calls.

`NewClient(Config)` separates Protocol, Provider label, BaseURL and Model. `Jev`, `OpenAI`, `H2O` supply defaults only. `Capabilities()` returns a value copy. Native MaxQuestions (0=uncapped), MaxChoices and MaxLevels may declare verified deployment limits; default maxima are 255 and 10. H2O conservatively inherits these defaults, not a claim about intrinsic model limits. OpenAI fixed official limits are not configurable.

`Request.Questions` is an ordered slice with unique `Name` strings (including empty string); result `Answers` is keyed by Name. Naming is this common SDK's policy; OpenAI wire names are optional. Native question IDs are authoritative; OpenAI position is authoritative and echoed name must agree. No searching/reordering to repair broken correspondence. Missing answer and mismatched kind/name are Invalid, not Refused. Only OpenAI `type:refusal` is Refused. Extra IDs/counts and malformed envelope metadata are top-level Issues; unusable answers containers or JSON fail the call.

Input/Instructions/Description accept Go JSON-marshalable values and are materialized once before validation/transport. Input must materialize as string/object/array; native instructions may be nil. Structured content is preserved for native questions. OpenAI common instructions/descriptions are text-only; no invented stringify conversion. Choice Value must materialize as string or bool. Bool unsupported natively. Illegal kind-specific fields cannot disappear silently.

Native mapping: predicate→noul, input→state, named question map; choice criteria map to exact string labels and descriptions/null; score label-only→string criterion, label+description→structured `{label,description}` criterion. Returned native score legend must structurally match sent criteria. OpenAI mapping: ordered questions, predicate/choice/score; input JSON becomes user message input_json with data. JSON must be object or array-of-objects (empty array allowed), max 32 container levels/10,000 values/256 KiB compact encoded JSON; native input max 64 container levels. Go's JSON encoding escapes HTML; byte checks conservatively use those exact encoded bytes.

Both protocols enforce finite probabilities/confidence [0,1], typed selection membership, complete unique candidate coverage and sum≈1 (absolute .01 tolerance); choices must be maximum-probability within .01. These are SDK validation policy, including where the OpenAI response schema permits empty arrays. Scores require integer indices, matching OpenAI labels/native legend, range 0..n-1, and probability-weighted score within .02. Scores and distributions are never overwritten or renormalized. Invalid results retain raw bytes for investigation. Absent numeric values remain nil, never fabricated zeros.

OpenAI native controls: nullable prompt_cache_key (64 Unicode codepoints), safety_identifier (128), prompt_cache_options (mode implicit/explicit/null and ttl 30m), and inputTextCacheBreakpoint bool for shared text. Explicit mode without breakpoint is valid and means no cache. JSON cannot carry a text marker. Unknown keys fail preflight. Native Options are direct allowlisted extension fields; protected common/excluded fields cannot be overwritten.

Raw is original response bytes, not re-encoded JSON. Usage nil means absent; `null` bytes means explicit null. Unknown top-level fields go into Metadata. Raw confidence remains provider-specific certainty, not universally calibrated correctness. Raw response model is separate from requested alias. Defaults use mutable aliases; pin models when repeatability matters. This package does not prove judgment equivalence between models or deployments.

Default byte limits: 32 MiB request / 8 MiB response, configurable positive up to 1 GiB. Timeout 30s, overridable by Config and caller context deadline. APIKey conflicts with Authorization headers. Body limit errors are whole-call errors. HTTP errors preserve status, allowlisted request IDs/Retry-After and explicit diagnostics. No retries/fallback/splitting, hidden I/O or telemetry. HTTPClient is copied while transport/jar are shared. Caller custom components must honor contexts; arbitrary user code cannot be forcibly stopped.

Not supported: rich media/assets/Box, conversation/tool history, arbitrary schema fields, server launch/download, full OpenAI SDK functionality, calibrated thresholds, pricing or model benchmarking. Use official SDKs for their broader provider surface. New adapters require current documented contracts and dedicated regression tests rather than URL-only compatibility claims.
